# 收藏、蚀刻章、分享功能检查记录

## 本轮修复

- 菜品详情的旧请求没有被真正丢弃：切换菜品后旧结果可能覆盖新页面，也可能改变分享卡片的数据源。现在读取和交互响应均检查本次页面请求的失效状态。
- 收藏、点赞、想吃清单状态被绑定到一次 Promise.all：附属接口失败会丢失其他成功结果。现在分别处理成功状态，并在初始状态加载结束前禁用操作，防止迟到的初始状态覆盖用户操作。
- 收藏响应和蚀刻章保存响应没有检查数据形状：代理返回 HTML 或异常响应时可能被当成成功。现在验证关键响应字段；列表接口验证数组形状。
- 蚀刻章未上色仍提交、重复触发保存、关闭编辑器后请求继续等交互问题已补齐；有效的服务器校验信息会显示，其他 HTTP 错误附带状态码。
- 蚀刻章 DTO 的颜色元素允许 null，服务端可能发生空指针错误。现在 DTO 和服务均拒绝无效颜色数组。
- 蚀刻章相同内容重复保存可能因 MySQL 返回零个变更行而误报不存在。现在独立校验所有权，不再将零个变更行等同于失败。
- 蚀刻章选择先清空再验证所有权。现在先验证目标归属，再更改选择。
- 删除蚀刻章失败没有 UI 错误处理。现在保留卡片、显示错误并允许重试。
- 个人主页重试可以重复启动并发加载，现加上运行锁。
- 分享卡片蚀刻章接口失败仍显示“尚无蚀刻章”。现在明确区分加载失败和真实空列表。

- mvn -q -f dayanfood-backend/pom.xml test：87 项通过，1 项 MySQL 显式启用测试跳过。
- npm run build --prefix web -- --outDir node_modules/.cache/profile-build：通过。默认 dist/audio 曾被占用，故使用独立输出目录；仍有现有主包大小警告。
- npm run test:collections --prefix web：通过。验证收藏/取消、附属接口失败、切菜竞态、空章、保存校验错误、创建后重载、未修改再保存、删除失败与重试。
- npm run test:share --prefix web：通过。验证桌面/手机导出、二维码实际解码、背景导入、资料接口异常、个人主页蚀刻章独立加载与恢复。

浏览器验收使用模拟 API 数据；HTTP 控制器测试使用 MockMvc，不能替代正式 MySQL 联调。

## 尚未确认

本地 MySQL 确实在监听，但使用现有配置尝试真实连接时返回 Access denied。未改数据库密码、表结构或数据，也没有对正式环境进行部署。

已提供 CollectionMysqlTests：设置 RUN_MYSQL_FLOW_TESTS=true、DB_PASSWORD（必要时 DB_URL、DB_USERNAME）后执行：
mvn -f dayanfood-backend/pom.xml -Dtest=CollectionMysqlTests test

它只允许 localhost/127.0.0.1，并用会话临时表遮蔽原表，验证收藏和自制蚀刻章的 MyBatis 实际读写；关闭连接时临时表销毁。需要本地测试库已包含相关 Flyway 表。不要将测试连接指向正式数据库。

正式环境的收藏与保存失败，仍需根据真实请求状态码、服务日志、所运行 JAR 和 Flyway 记录确认。本轮代码修复不等同于正式环境已恢复。
